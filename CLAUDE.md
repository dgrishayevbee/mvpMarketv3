# CLAUDE.md — mvpMarket v3

Читается автоматически в начале каждой сессии Claude Code. Здесь только то,
что нужно знать перед правкой кода. Архитектура и история решений —
в `docs/ARCHITECTURE.md`.

## Что это за проект

Третья итерация B2B маркетплейс-прототипа (первая — `dgrishayevbee/mvpMarket`,
вторая — `dgrishayevbee/mvpMarketv2`). Продукт тот же: единственный поставщик товаров —
сама платформа, не независимые продавцы. Чисто визуальный прототип: без
бэкенда, без БД, без реальной авторизации.

**Отличие от второй версии — только палитра.** Код снят с mvpMarketv2 на
коммите `f35e70e` целиком; расходится один файл, `src/styles/tokens.css`.
Идея гибрида: типографика и чистота дизайн-системы Claude (Literata в
заголовках) поверх цветов Beeline. Если ради палитры пришлось править
компонент — там протёк хардкод, чини его, а не обходи.

Предыдущие версии живут на своих URL и служат референсом для сравнения.
Заглядывать в них за логикой можно, копировать оттуда CSS — нельзя.

## Текущее состояние

Все экраны собраны на дизайн-системе Beeline Business. Заглушек не осталось.
Работает сквозной поток: каталог → корзина → заявка → кабинет → кабинет
поставщика.

Дизайн-система лежит в `docs/design-system/` (экспорт Claude Design:
библиотека, DS-BASE.md со сниппетами, шаблон экрана). Токены из её
helmet-блока перенесены в `src/styles/tokens.css` один в один.

## Стек

React + Vite, React Router, React Context + localStorage (без Redux, без
сервера). Дизайн-система — CSS-переменные в `src/styles/tokens.css`.

## Структура

```
src/
  styles/          tokens.css (переменные дизайна), global.css
  components/
    ui/            кит по ДС: Button, Card, Chip, Tag/Status, Field,
                    Price, Checklist, Notice, Metric, Row, IconTile,
                    Steps (шаги мастера), icons
    layout/        Layout (топбар + сайдбар каталога), PageHead/SectionHead
    product/       ProductCard
    catalog/       PlansSection — колонки тарифов, HeroSearch
  context/         Auth, Content, Products, Cart, Favorites, Orders, UI
  hooks/           useLocalStorage
  data/            siteContent.js — единственный источник контента главной

```

Появятся по мере надобности: `components/overlay/` (оверлеи в ДС пока не
описаны).

## Навигация и покупка

Сайдбар взят из первой версии и живёт в `Layout`: категории каталога,
быстрые ссылки, неактивная поддержка. Активная категория не хранится в
состоянии главной, а лежит в query (`/?category=connect`) — сайдбар в
каркасе, каталог на главной, общий адрес дешевле общего контекста. Чипов
над сеткой нет, это был бы второй контрол на тот же фильтр. Служебные
экраны (кабинет, поставщик, контент) — текстовые ссылки в топбаре.

Покупка идёт тремя шагами: заказ → оплата → подтверждение. Между первым и
вторым стоит гейт: услуги подключаются на юрлицо, поэтому без аккаунта
компании дальше не пройти, и гейт ведёт в мастер регистрации по ЭЦП
(`/register`) с `?next=`. Мастер из четырёх шагов — ключ, сертификат,
биометрия, подписание — мокается таймерами, но с временем подписи и
отпечатком: это прототип флоу, а не заглушка. Не упрощай его обратно в
одну форму.

## Правила дизайн-системы (не нарушать)

Полный список — `docs/design-system/DS-RULES.md`. Главное:

- Фон страницы `--bg` (нейтральный off-white), поверхности `--surface`.
  Чистый белый фон страницы не использовать.
- Карточка без тени; тень `--shadow-sm` только на hover, без подъёма и
  масштабирования.
- Акцент действия — жёлтый `--accent` (#FFCC00) с тёмным `--accent-ink`.
  Синего нет. В v3 это осознанное отступление от правила исходной ДС, где
  акцентом был чёрный, а жёлтый — только бренд-маркер: см. раздел 7.1
  `docs/ARCHITECTURE.md`.
- Жёлтый — только заливка под текстом (кнопка, активный чип, solid-тег,
  бейдж). На тонких линиях и в тексте он даёт 1.5:1 на белом и не виден:
  фокус берёт `--focus`, полосы и ховер ссылок — `--ink`. Не привязывай
  фокус-ринг обратно к `--accent`.
- Одна primary-кнопка на экран.
- Serif (`--font-serif`) — заголовки и метрики. Цены и суммы — sans 600 +
  `font-variant-numeric: tabular-nums`. Serif для цен не использовать.
- Статусы — цветной текст плюс точка 6px. Тонированный фон (`--*-bg`) — только
  для одной полосы-уведомления на экран.
- Иконки линейные: `fill="none"`, `stroke="currentColor"`, 1.4 на 15-16px и
  1.25 на 20-28px. Залитых, цветных и эмодзи нет.
- Отступы кратны 4: внутри карточек 20-28px, между блоками 32-72px.
- Деньги в тенге, разряд обычным пробелом: `7 900 ₸`.

## Правила работы с кодом

- Все цвета, шрифты, spacing, радиусы, тени — из `src/styles/tokens.css`.
  Никогда не хардкодь hex-цвета или px-значения, которые уже есть в токенах.
  Нет нужного токена — добавь его в tokens.css, а не значение в компонент.
- Контент главной (тексты, карточки, тарифы, пакеты) живёт в
  `src/data/siteContent.js` и правится через `ContentContext`, а не напрямую
  в JSX.
- **Поменял состав массива в `siteContent.js` — подними `CONTENT_VERSION`.**
  Сохранённая в localStorage копия мержится поверх дефолтов, и для массивов
  состав берётся из сохранённого: удалённые элементы вернутся, а
  переименованные останутся со старым текстом. У всех, кто уже открывал
  сайт, правка просто не появится. Добавление нового ключа-объекта
  (например `hero`) домешивается само и бампа не требует.
- `CartContext` общий для всех точек добавления в корзину. Не создавай
  отдельную логику корзины внутри компонента.
- Изображений по умолчанию нет. Не вставляй случайные внешние картинки
  без запроса.
- Фокус вёрстки — десктоп. Не хардкодь desktop-only размеры в логике
  компонентов, разделяй layout- и контент-компоненты.
- Перед любой правкой ширины/выравнивания блока (`width`, `max-width`,
  `margin`, `display`, `grid-template`, `flex`) читай раздел 6.1
  `docs/ARCHITECTURE.md` — «Грабли вёрстки». Главное оттуда: `max-width` +
  `margin-inline: auto` на flex-элементе схлопывает его в shrink-to-fit;
  центрируется явной шириной `width: min(100%, N px)`.
- Сломал что-то на живом сайте — после фикса допиши случай в 6.1 одной
  строкой: что сделал, что сломалось, как правильно.

## Git

Прод-ветка — `main`, её деплоит Vercel. Коммить и пушь сразу в неё, отдельные
ветки и Pull Request не нужны: ревью никто не делает, проверка идёт вручную
на живом сайте после деплоя.

## Формат ответа

- Не читай файлы, которые не относятся к задаче.
- Не переписывай компонент целиком ради маленькой правки — точечный диф.
- После изменений не давай длинный пересказ — краткое резюме дифом.
- Не запускай `npm run build` или `npm run dev` самостоятельно, если явно
  не попросили. Исключение — layout-правка: её по чек-листу из 6.1 надо
  проверить скриншотом до пуша, потому что пуш сразу уходит в прод.

## Команды

```bash
npm install
npm run dev       # dev-сервер, обычно localhost:5173
npm run build     # сборка в dist/
npm run preview   # локальный просмотр сборки
```

Деплой — Vercel, автоматом по пушу в `main`. `vercel.json` настроен на SPA
fallback, трогать не нужно.
